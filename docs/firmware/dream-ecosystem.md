# Dream ecosystem

Dream explicitly markets reference designs for digital wind instruments. Its SAM5000 series combines a proprietary P16XT CPU, P24XT DSP cores and external memory interfaces. The SAM5504B is a plausible low-cost USB synth candidate. SAM2695 and SAM2635 have no native USB in their public interface lists and remain possible as secondary sound chips. A separate USB controller remains possible. [Dream applications](https://dream.fr/applications/) · [Device matrix](https://www.docs.dream.fr/devices.html) · [SAM5504B datasheet](https://docs.dream.fr/pdf/Serie5000/SAM_Datasheets/SAM5504B.pdf)

## Other products and update paths

- **Dream 5504-EK and 5704PIA-DK.** Manufacturer examples pair a known board layout, raw boot/application images and SAM2DFU packaging. Dream's public 5504 reference uses USB MIDI for performance and a separate debug adapter for development. [5504 reference](https://docs.dream.fr/pdf/Serie5000/Boards_Datasheets/5504-DK_REV1.pdf) · [Container experiment](../experiments/2026-11-26-dream-reference-files.md)
- **Serdaco DreamBlaster X16/X16GS, SAM5716B.** X16 Manager identifies firmware slots in a dedicated boot mode. The downloadable v1.04 update is a raw Dream-marker candidate without a DFU suffix. The manager's transport framing remains unverified. [X16 user manual](https://serdaco.com/downloads/X16/X16_Documentation/DreamBlaster%20X16%20User%20Manual.pdf) · [Serdaco chip identification](https://serdaco.com/downloads/X16/X16_Documentation/Converting%20SF2%20soundfonts%20to%20X16%20DreamBlaster%20soundbanks.pdf)
- **Serdaco DreamBlaster X2.** The vendor's loader uses the module's MIDI ports and displays a model and firmware version. It loads product-specific DXB banks and DXP presets. That is evidence of a separate MIDI-based identification and write workflow on the X2. It provides no public evidence of a compatible query on the EWI. [X2 user manual](https://www.serdaco.com/downloads/X2/X2_Documentation/DreamBlaster%20X2%20User%20Manual.pdf)
- **V3 Sound expanders.** V3 documents model-specific ZIPs containing BIN bank files for USB-stick updates. This is another transport and packaging workflow. It cannot establish an EWI update procedure. [V3 Sound procedure](https://v3sound.com/en-update-flash-memory.html)

## Read-only identification boundary

The EWI's normal USB configuration exposes only USB Audio Control and MIDI Streaming. No runtime DFU or vendor/RPC interface was present in the captured descriptor tree. USB `bcdDevice` is a descriptor release field. It is not a verified application version. Standard USB DFU has read/status commands and optional firmware upload, but upload requires a matching DFU-mode interface and advertised capability. The Dream guide documents an update workflow and does not establish firmware upload support for this EWI. The documented SAM5704B ROM host fallback receives an image in RAM through a hardware interface. It is not a USB firmware extraction feature. [USB DFU specification](https://www.usb.org/document-library/device-firmware-upgrade-11-new-version-31-aug-2004) · [SAM5704B datasheet](https://docs.dream.fr/pdf/Serie5000/SAM_Datasheets/SAM5704B.pdf)

The immediately testable read-only operations are descriptor inspection, MIDI Universal Identity Request and offline analysis of public reference packages. Vendor-specific identification can proceed against this instrument if an attributable OEM utility or protocol specification supplies a clearly read-only operation. Dream RPC, X2 loader discovery, DSP Designer controls, and DFU runtime commands are unverified for this instrument.

Konix publishes DC02 and DC02 Pro manuals on its downloads page. The listings checked contained no firmware or updater for those variants. [Konix downloads](https://www.konixtech.com/download/)
